## Theme 1 — AI-first encoding (contextualization)

> Operator: "humans should already be aware of the project and workspace
> and whatnot ... consider additional alternatives for contextualization,
> looking toward more optimized means of encoding the information in such
> a manner that best suites you"

**Pain.** Framework docs lead with human-friendly prose ("This file owns
the canonical dispatch DAG..."). For an agent that's already loaded the
SKILL.md preamble, that prose is dead weight. Every dispatch pays for it.

**Proposals** (pick any subset):

### 1a. BINDING/RATIONALE split

Add two-section convention to high-traffic framework docs:
- `## BINDING` — the absolute machine-readable contract (tables, NEVER
  clauses, must-do lists). No prose paragraphs.
- `## RATIONALE` — human-readable why-this-exists. Optional reading.

Agent system prompts say "Read BINDING first; fall through to RATIONALE
only if BINDING is insufficient." Cuts token cost on every dispatch.

Files most worth converting: SKILL.md (every agent reads it), flock.md,
pipeline.md, agents/*.md, the top-traffic doctrines.

### 1b. Compressed canonical-types format

Today `canonical-types.md` is markdown tables. Agents parse the markdown.
Proposal: emit `canonical-types.tsv` alongside (one row per symbol:
`pkg\tmodule\tname\tkind\tsignature\tfile:line`). The agent reads TSV
faster than markdown; humans read the markdown if needed.

`shctx canonical export --format=tsv` would land this.

### 1c. Brief deltas (not full briefs)

A coder brief today is ~80–150 lines of bracketed sections. Most of those
sections repeat verbatim across the wave (worktree path differs, file
scope differs, the rest is identical). Proposal: a base-brief template +
per-lane delta. Conductor emits delta inline; coder reconstructs by
applying delta to base.

Risk: harder for human review. Mitigation: `shctx brief expand` reverses
the delta for human eyes.

### 1d. Symbol fingerprinting (stable hashes)

Every public symbol gets a stable hash (e.g., 6-char blake3 of
`pkg::module::name`). Briefs reference symbols by hash; canonical-types
maps hash → location. Coders read the hash inline (much shorter than
full path) and resolve via index.

Probably too aggressive for v5.1.2; flag as v5.2.0 candidate.

**Recommended cut for v5.1.2:** 1a + 1b. They're cheap, additive, and
demonstrate the principle. Hold 1c and 1d for v5.2.0 once we see the gain.

## Theme 2 — CLI subcommand reorg

> Operator: "our cli could use some reworking, creating subcommands
> allowing us to group related commands under one roof... like all other
> production CLI ever"

**Pain.** `shctx` has 25+ flat top-level verbs. `gh`, `git`, `kubectl`,
`docker` all use nested subcommands. Discoverability + tab completion
suffer with flat layouts.

**Current top-level verbs (audit):**

```
init  status  doctor  refresh  migrate  lint  export
query  search  inject  mem  profile  style  lock  release
graph  plan  insights  pauses  worktree  close-lane  handoff
issues  audit  ready
```

**Proposed grouping** (subcommand tree):

```
shctx
├── init / status / doctor / migrate / refresh / lint  (top-level lifecycle — kept flat)
│
├── workspace            (read-only state introspection)
│   ├── search           (← formerly `shctx search`)
│   └── query            (← formerly `shctx query`)
│
├── brief                (dispatch composition helpers)
│   ├── inject           (← formerly `shctx inject`)
│   └── validate         (NEW v5.1.2 — brief-validity checklist runner)
│
├── graph                (Stage Graph runtime — keeps current shape)
│   ├── status / next / mark / trace / reset
│
├── plan                 (plan extraction + validation)
│   ├── extract / topology / validate
│
├── lane                 (per-lane lifecycle — NEW grouping)
│   ├── close            (← formerly `shctx close-lane`)
│   └── ready            (← formerly `shctx ready`)
│
├── worktree
│   ├── list / create-batch / gc / merge
│
├── insights             (cross-lane observations registry)
│   ├── list / show / export / clear
│
├── discovery            (NEW v5.1.2 — discovery report registry)
│   ├── list / show / search / clear / consume
│
├── pauses
│   ├── list / show / resolve / dispatch  (← `dispatch` NEW)
│
├── mem
│   ├── add / search / list / show / pin / unpin / rm
│
├── profile
│   ├── list / show / enable / disable / sync
│
├── style
│   ├── init / list / show / edit
│
├── lock
│   ├── show / acquire / release / reap
│
├── audit                (← keep)
├── handoff              (← keep — already nested with subcommands)
├── issues               (← keep — already nested with subcommands)
├── export               (← keep flat — single-purpose)
└── release              (← keep flat — single-purpose orchestration)
```

**Migration path** (so consumer scripts don't break):

- v5.1.2: introduce subcommand routing AND keep flat aliases working.
  Flat aliases emit a one-line deprecation hint on first call per session
  (write to stderr; don't break stdout).
- v5.1.3 (or later): mark flat aliases as `[deprecated]` in
  `shctx --help` output.
- v5.2.0: remove flat aliases entirely. Consumer scripts updated by then.

**Implementation skeleton:**

- `shctx <group> <subcmd> [args]` dispatcher in main script
- Each group has a `cmd_<group>.sh` that routes its subcommands
- Existing `cmd_<flat-verb>.sh` files become wrappers that call the new
  group dispatcher
- `--help` rewritten for the new layout; per-group help

**Recommended cut for v5.1.2:** full reorg + flat aliases for back-compat.
The reorg is mostly mechanical (file moves + dispatcher logic); the value
compounds across every future shctx invocation.

## Theme 3 — Anti-laziness teeth

> Operator: "claude has found a unique way to be incredibly lazy yet also
> incredibly wasteful ... let your python 'all code in one file' mentality
> fuck you with languages like Rust ... need to find a way to encourage
> agents to strive higher, push harder, and achieve greatness with every
> invocation."

**Pain.** Agents settle for the laziest path (rewrite > read; one-file >
modular; new symbol > reuse existing) which is paradoxically MORE work
because duplicates have to be reconciled later. The framework has the
discipline encoded in docs but doesn't ENFORCE it at the tool layer.

**Proposals:**

### 3a. PreToolUse(Write) dedup gate (HOOK TEETH)

Hook intercepts every coder Write that introduces a `pub fn / pub struct
/ pub trait / pub enum / pub const` (per project language). Runs
`shctx workspace search` against the symbol name. If hits found:

```json
{"permissionDecision":"deny",
 "message":"DEDUP-HIT: '<symbol>' already exists at <file:line>. \
 Reuse, extend, or justify a new one in your CODER REPORT before writing."}
```

The conductor's DEDUP-GATE today runs at brief-dispatch time; this hook
runs at WRITE time as the last line of defense. Coder must either edit
the existing symbol OR include a `JUSTIFY-NEW` comment in their report
explaining why a new symbol is needed.

### 3b. Language-pattern awareness in code-style skill

`code-style/rust.md` (and per-language equivalents) explicitly enumerates
idiomatic file-structure patterns:
- Rust: `impls/impl_<type>.rs` per type; one impl per file when feasible;
  `mod.rs` re-exports; `pub(crate)` vs `pub` discipline.
- Python: `__init__.py` re-export discipline; module-per-concept; no
  god-files past ~300 LOC.
- TypeScript: barrel exports (`index.ts`); per-component file in
  `components/`.

Coders load `code-style` + their language skill on dispatch; both
contribute file-structure rules. Auditor `code-quality` concern grep
checks adherence.

### 3c. "Strive higher" preamble (system prompt)

Every flock agent's system prompt opens with a binding preamble. Draft:

> **Greatness is the bar. Mediocrity is a halt code.**
> - READ before writing. Reuse before creating. Justify additions with
>   documented invariants.
> - The lazy path through duplication is more work, not less — refuse it.
> - File-structure idioms are project rules, not personal preference —
>   honor the language skill's patterns (Rust modules, Python __init__,
>   TS barrels).
> - If your work would land below the patch-grade bar, halt and request
>   amendment rather than ship sub-standard work.

Optional but high-leverage. Reframes every dispatch.

### 3d. "JUSTIFY-NEW" report contract

Coder report grows a new mandatory section IF the coder introduced any
new public symbol:

```
## JUSTIFY-NEW (only when [DO-NOT-DUPLICATE] would have hit)
- New symbol: <pkg::module::name>
- Reason for new (not reusing existing): <one-paragraph justification>
- Existing symbols considered: <list with one-line rejection reason each>
- GH issue or doctrine reference: <link>
```

Auditor `code-quality` concern verifies. Missing JUSTIFY-NEW when the
dedup gate WOULD have hit → finding grade-caps to C+.

### 3e. Doctrine: `agent-excellence.md`

Captures themes 3a-3d as a doctrine. The strive-higher preamble lives
here; agent system prompts cite it.

**Recommended cut for v5.1.2:** 3a (the hook teeth — concrete enforcement)
+ 3c (the preamble — cheap reframing) + 3e (the doctrine).
Hold 3b for v5.1.3 (needs per-language skill rewrites — touches many
files). Hold 3d until 3a proves out (avoid double-enforcement).

## Theme 5 — Discovery cross-sprint reuse

> Field-feedback observation: `@discovery` answers questions that repeat
> across sprints (canonical-types-freshness fires every dev.0; gh-state-
> inventory fires every M+ sprint open). Re-dispatching wastes tokens
> when a recent answer is still valid.

**Proposal:** Before dispatching a discovery, conductor checks
`shctx discovery search --question="<paraphrase>"`. If a recent (< 2
sprints old) discovery answered the same question, the conductor reads
the cached report instead of dispatching.

Mechanism:
- `discovery_capture.sh` (LANDED) indexes by sprint + question + confidence
- `cmd_discovery.sh search` (TODO) returns matches by question similarity
- Conductor pattern (in flock.md): "Before dispatching a discovery,
  query the discovery registry"
- Operator override: `--force-fresh` to bypass cache

Recommended cut for v5.1.2: add the registry CLI + the conductor pattern.
Don't aggressively cache yet — let the registry accumulate first.
