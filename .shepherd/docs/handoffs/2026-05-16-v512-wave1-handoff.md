## Hard-won process discipline this session (do NOT repeat)

These are corrections the operator gave me; persisting in memory entries (see below):

1. **Don't bypass PRs.** Branch protection on main is enforced by humans, not by errors. Always `gh pr list --state all` before any git surgery.
2. **Don't defer work when operator wants it shipped now.** v5.1.1 release notes documented hooks/doctor as "planned for v5.1.2" — operator interpreted as me being lazy. Half-shipping is worse than asking for confirmation that scope is full.
3. **Match version refs to actual branch state.** I bounced from v6.0.0 → v5.2.0 → v5.1.0 → v5.1.1 → v5.1.2 by repeatedly mis-reading what was already released. Always `git log --oneline -5` + `gh release list` BEFORE assuming a version target.
4. **Verify cited file paths in plans/seeds against the filesystem before commit.** I caught my own drift (`agents/agent-excellence.md` → `skills/shepherd/doctrines/agent-excellence.md`) during a self-audit; the planter pattern (operator-reported) drops `.rs` suffixes turning files into dirs. Always `[[ -f "$path" ]]` or `Glob` before citing.
5. **Don't dispatch coder agents for shepherd-on-shepherd self-dev when the conductor (Opus) can do it inline faster.** The framework wants flock-dispatch by default; abbreviated mode is fine for plugin self-dev where the conductor IS the developer.
6. **Slug form vs branch form.** Branches keep dots (`v5.1.2-dev.3`); filenames collapse them (`v512-dev3.seed.md`). The dotted-bleed was a planter drift documented in `doctrines/seed-naming.md`.
