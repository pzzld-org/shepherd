# v6.2.5 — model table, engineer self-containment + critic-proof, workdir prune

Status: approved 2026-07-01. Branch `v6.2.5`, draft PR #168. Behavioral / config / CLI wiring only, no heavy architecture.

## Why (outcomes this moves)

- **(B)** Operators (Joe) hand-pin conductor models on every spawn. One `[models]` table in `.claude/shepherd.toml` makes per-role model selection declarative, so at ultra-parallel scale for long durations there is one place to map models to subagents and one fewer class of error. Measurable: `shctx models show` reflects config; dispatched agents run the configured model.
- **(A)** Root re-critiques plans the engineer already reviewed, burning tokens and coupling tiers. Move discovery + critic **inside** the engineer teammate and make root's acceptance a mechanical gate backed by a **critic-proof** (irrefutable evidence the plan was critiqued and edited ≥1 time). Measurable: presence + validity of `critic-proof.json`; `shctx plan verify` pass/block; root does zero re-critique.
- **(C)** No workdir GC exists beyond teammate pruning; `.artifacts/` accretes stale dispatch dirs, logs, snapshots, terminal DB rows. `shctx prune` reclaims them safely. Measurable: rows/files pruned, DB size delta, must-keep survival = 100%.

5. C ships **first-cut**: on-disk targets execute now; DB-row targets ship dry-run-first, enabled over time. `--dry-run` is the default.

## (A) Engineer self-containment + plan/lane doctrine + critic-proof

### Purpose re-emphasis

The engineer's entire reason to exist: take the **seed + current context** and produce **one actionable multi-phase plan**. Each phase holds N granular tasks/stages that may be **conditionally linked** for near-automatic execution. The plan is then sliced **vertically into independent lanes** (cohesive slices across phases). Each lane maps to a team led by a **conductor** who runs dynamic workflows dispatching **coder/worker waves** with **auditor self-review**. Sharpened in `agents/engineer.md` and the new doctrine.

### Self-containment

When dispatched as a teammate, the engineer runs its own discovery wave and `@critic` gate as in-session Agent-tool subagents, then edits the plan in response. It returns a plan payload plus the critic-proof. Root does not re-review substance.

Relax `commands/spawn.md` root-tier-exclusive restriction so the engineer teammate may dispatch discovery/critic in-session.

### Critic-proof (the teeth)

Deterministic artifact tying the critique to the exact plan bytes. Written to the plan's docs dir as `critic-proof.json`:

```json
{
  "sprint": "v6.2.5",
  "plan_path": "<relative path to plan>",
  "pre_critic_hash": "sha256:<plan bytes BEFORE the critic pass>",
  "post_critic_hash": "sha256:<plan bytes AFTER edits>",
  "edited": true,
  "critic": { "verdict": "PASS", "iterations": 1, "findings": <n> },
  "recorded_at": "<iso8601>"
}
```

- Engineer records it: `shctx plan record-critique --plan <path> --pre <hash> --verdict <v> --iterations <n> --findings <n>`. The command computes `post_critic_hash` from the current plan file, sets `edited = pre != post`, and writes the JSON.
- Root verifies it: `shctx plan verify --plan <path>` (mirrors the v6.2.1 `shctx seed verify` blocking gate). Checks, all required:
  - `critic-proof.json` exists for this plan.
  - `edited == true` and `pre_critic_hash != post_critic_hash` → else `PLAN-UNEDITED`.
  - `post_critic_hash` equals the **actual current plan file hash** → else `CRITIC-PROOF-STALE` (cannot be fooled by a proof describing an older plan).
  - `critic.verdict` present and not a hard `FAIL`; `iterations >= 1` → else `PLAN-UNCRITIQUED`.
  - Missing file → `CRITIC-PROOF-MISSING`.

Latent critic produces findings; the deterministic hash-proof + verifier makes the flow irrefutable forever after.

## (B) The `[models]` table

### Config

Exact table works verbatim:

```toml
[models]
root      = "opus[1m]"
planter   = "opus[1m]"
engineer  = "opus[1m]"
conductor = "sonnet"
critic    = "sonnet"
discovery = "sonnet"
coder     = "sonnet"
auditor   = "sonnet"
worker    = "sonnet"
```

`cfg_get` is section-agnostic bare-key today. Add a section-aware reader `cfg_section_get <section> <key>` to `skills/context/scripts/_lib.sh` and mirror it in `hooks/scripts/_lib.sh` (the two copies must stay in sync per the contract comment). Bare keys under `[models]` resolve without collision.

### Resolution chain (forward-compatible)

```
shctx models resolve <role>:
  1. explicit [models].<role> key      ← ships now
  2. active profile/mode preset        ← future (deferred)
  3. root-tier-derived default         ← future (deferred)
  4. built-in default                  ← ships now (= stated defaults)
```

Built-in defaults equal the table above, so zero-config behavior = stated defaults.

### Dispatch wiring (pin-injection)

Every dispatching tier resolves the target role's model via `shctx models resolve <role>` and passes it as the Agent tool `model` param / teammate spawn pin. Generalizes the existing v6.0.9 conductor pin. The conductor cost advisory is preserved: if `conductor` resolves to an opus tier, the pre-spawn advisory still fires.

Root row is advisory only: a SessionStart/spawn preflight warns once if the live session model differs from `[models].root`. Root frontmatter stays `model: inherit`.

## (C) Workdir prune — first-cut

### gitignore fix

Add `.artifacts/memory/` and `.shepherd/memory/` to `.gitignore` (precompact snapshots currently leak into git status).

### `shctx prune`

New `skills/context/scripts/cmd_prune.sh`:

- `--dry-run` is the **default**; `--confirm` executes.
- Snapshots affected DB rows + file lists to `/tmp/shepherd-prune-<epoch>/` before any delete; writes a before/after CSV. Prints the CSV path.
- Fence for eligibility (all three required): sprint/branch != current git branch, terminal status, age >= floor.
- Every DB DELETE guarded against a missing table (this repo's DB has only migrations {1,2,7}; guard with a `sqlite_master` existence check).
- WAL checkpoint after deletes; `VACUUM` behind `--vacuum`.

**Executes now (on-disk):**
- stale dispatch dirs (`.artifacts/dispatch/<sprint>/` where sprint != current branch),
- aged logs (`logs/events-*.jsonl`, `logs/hooks/*.jsonl` older than `logs_days`),
- orphan precompact snapshots beyond `snapshots_keep`.

**Dry-run-first (DB rows), enabled over time:**
- `logs_events` (observability), crashed/retired-teammate `heartbeats`, `mailbox` acked or past `expires_at`, closed-sprint `discovery_findings`/`audit_findings` (already harvested to priors), `loops` in converged/cap-reached/aborted, released `locks_history`.

**Never touches:** `index_releases`, current-sprint `focus`, `sprint_metrics`, pinned/doctrine/decision `mem_entries`, unresolved `escalations`, pending `deliverables`, active `locks` (`released_at IS NULL`), active `loops`, whole `index_*`/`projects` core, tracked `.artifacts/docs/`.

### Config

```toml
[prune]
logs_days      = 60
dispatch_days  = 30
snapshots_keep = 20
findings_sprints = 6
```
