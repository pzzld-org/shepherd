# Example — `shctx inject coder` output

Sample `[DB-CONTEXT]` block as it appears in a coder brief's `[CONTEXT-INVENTORY]` section. Generated by `shctx inject coder` and pasted by the engineer at plan-time.

The block is a structural contract (per `flock.md` § @coder, milestone c optional / milestone d required). The coder reads `[DB-CONTEXT]` as authoritative for overlap detection — if the lane introduces a type that overlaps with a row below, the coder MUST cite that row in `[CONTEXT-INVENTORY]` and either reuse it or escalate.

---

## Invocation

```bash
shctx inject coder
```

Defaults: top-30 most-referenced public symbols for the active project, formatted as a markdown pipe-table. Use `--limit=N` to widen, `--package=<glob>` to scope.

## Coder usage contract

When the coder receives a brief with this block:

1. Scan every row before drafting types in this lane.
2. If the lane's planned new symbol overlaps a `name` or a `concept`, cite that row in `[CONTEXT-INVENTORY]` and **wire to existing**; do not introduce a near-duplicate.
3. If the overlap is structural but the existing symbol is unsuitable, surface the conflict — do not silently shadow.
4. If `[DB-CONTEXT]` is absent (milestone c, fall-back path), proceed with the markdown `canonical-types.md` as usual.

The conductor's DEDUP-GATE (`shctx query dedup-check --name=<symbol>`) runs the same check pre-dispatch; the in-brief `[DB-CONTEXT]` is the coder-side echo.

See `${CLAUDE_PLUGIN_ROOT}/skills/shepherd/doctrines/zero-duplicate-tolerance.md` for the full Layer 1/2/3 model.
