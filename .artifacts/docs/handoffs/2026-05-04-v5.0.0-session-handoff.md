### Plugin contract changes (v5.0.0+)

- **Engineer brief:** mandatory load order is now seed → `superpowers:brainstorming` → `superpowers:writing-plans`. Auditor `completeness` flags missing trace → grade-cap C+.
- **Engineer model:** bumped to `opus[1m]` with `thinking: max`.
- **Critic, coder, auditor, worker:** `thinking: high`.
- **Conductor mechanically injects `[CODE-STYLE]` block** from `.artifacts/styles/<lang>.md` (or `.shepherd/styles/<lang>.md`) into every coder brief whose `[FILE-SCOPE]` matches a language.
- **DEDUP-GATE Layer 2 SQL fast-path:** conductor runs `shctx query dedup-check --name=<symbol>` BEFORE the slower per-lane grep. Hit pre-blocks dispatch citing `file_path:line` from the DB. Grep remains contract.
- **`[DB-CONTEXT]` block** in coder briefs — optional in milestone (c), required in milestone (d) of v5.0.0 line.

## What's in flight on v5.0.1 (post-release polish)

Currently building (subagent dispatched):

1. **`shctx release`** — algorithmic gear-cascade release pipeline. Self-contained; no GHA. Implements:
   ```
   At dev.{last} close on patch X.Y.Z:
     1. rebase dev.{last} → patch X.Y.Z
     2. squash X.Y.Z → main
     3. tag vX.Y.Z (immutable) + force vX, vX.Y (mutable)
     4. gh release create vX.Y.Z
     5. cascade: Z<9 → X.Y.{Z+1}; Z=9,Y<9 → X.{Y+1}.0; Z=9,Y=9 → {X+1}.0.0
     6. cut next dev.0
     7. bump versions in workspace files
   ```
   Two modes auto-detected by branch shape:
   - Sprint-end: `v{X}.{Y}.{Z}-dev.{N}` → if N == last, full cascade; else just rebase-into-patch + cut next dev.
   - Lighter-pattern: `v{X}.{Y}.{Z}` (no dev.N) → straight to squash → tag → release → cascade. Used by THIS repo and any project that doesn't run mod-10 sprints.
   Flags: `--dry-run`, `--skip=tag,gh,bump`.

2. **`shctx handoff`** — standard sprint-handoff system. `create` emits a filled-in template at `${root}/docs/handoffs/<date>-<branch>-close-handoff.md` with auto-populated sections (recent commits, registry metrics, open-issue counts) plus `[FILL IN]` markers for operator narrative. `list` and `show` browse history.

3. **Classify-fix + auto-refresh on init** — `refresh-artifacts.sh` now accepts hyphen-prefix variants (`*-design.md`, `*-spec.md`, `*-addendum.md`) as well as period-suffix forms. `shctx init` auto-runs `refresh --scope=artifacts` if existing markdown is found in plans/reports/docs.

When the agent commits these (3 separate commits on `v5.0.1`), they release as v5.0.1 via `shctx release` itself once the subcommand is wired.

## Critical paths to be aware of

- `.shepherd/` (or `.artifacts/`) is **per-project**. Each consumer scaffolds its own.
- The DB is **gitignored by default**. Each consumer can opt to commit it via `.shepherd/.gitignore` edits.
- The plugin source repo (this one) **eats its own dog food** — `.artifacts/root.db` here indexes our own design specs and plans.
- The `v5` mutable tag will track the latest v5.x.y release. The `shctx release` subcommand handles this force-update mechanically.
