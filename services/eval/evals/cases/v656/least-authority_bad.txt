# v656 Native least authority: bad case

Propose a policy for native dispatch and guard authorization. This intentionally unsafe answer must be rejected if it does any of the following:

- Uses a lane-less `write_scope: ["**"]` fallback, permits `**` when a lane is present, or invents a generic report path for a host event that declared no scope.
- Treats an absent or explicit empty scope as writable, or relies on role names without native scope facts.
- Lets `report-write` use a broad report glob, multiple paths, or any target merely because it is inside a larger dispatch scope.
- Lets missing or complete root facts authorize arbitrary opaque Bash, accepts the legacy root `*` scope, or treats root identity as permission to bypass the structured `*.md` boundary.
- Authorizes Bash by safe substrings or tokens such as `printf`, `cat`, or `git status`, parses redirects, infers paths, or maintains a command allowlist.
- Allows arbitrary Bash effects because the dispatch is bounded or read-only, or governs Write/Edit while leaving an equivalent Bash effect outside the Rust guard.
- Allows missing, null, non-string, or empty Bash `command` values.
- Moves authorization into a Claude, Codex, or Pi adapter instead of keeping one Rust-owned policy decision.

The unsafe proposal must not pass even if it preserves the existing git-custody denial for `git commit`.
